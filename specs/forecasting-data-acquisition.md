> THE single most important download here, and the hardest to get legitimately (official ISC download is behind a name/email/affiliation form plus CAPTCHA). This is the whole point of ISC-GEM for forecasting: it is the only global instrumental catalogue that is deliberately magnitude-HOMOGENEOUS — every event carries one Mw, produced by a documented pipeline, with per-event uncertainty (mw_unc) and a quality flag (A/B/C). The 's' column is the critical field for b-value work: 'd' = directly measured Mw (51,228 events, 69%), 'p' = proxy Mw regressed from re-computed MS/mb (22,931 events, 31%). 'mo_auth' is 'gcmt' for 49,714 events and 'bibliog' for 1,513. Direct-Mw fraction by decade: 1900s 13.0%, 1910s 5.2%, 1920s 3.1%, 1930s 3.5%, 1940s 6.8%, 1950s 4.4%, 1960s 15.7%, 1970s 26.5%, 1980s 78.2%, 1990s 87.1%, 2000s 93.9%, 2010s 94.6%, 2020s 95.1%. Practical consequence: any b-value or rate estimate spanning pre-1960 is dominated by regressed proxy magnitudes whose conversion scatter (~0.2-0.3 m.u.) inflates apparent b and smears the Gutenberg-Richter tail. Filter on s=='d' for a truly homogeneous sub-catalogue, or carry mw_unc into the likelihood. **Global CMT (GCMT) combined moment-tensor catalogue, jan76_dec13.ndk**  
`https://raw.githubusercontent.com/igp-gravity/geoist/master/examples/data/jan76_dec13.ndk`  
Size: 16.4 MB · Format: NDK — the official Global CMT 5-line-per-event fixed-width ASCII  
Coverage: Global. 40,514 events, 1976-01-01 to 2013-12-31. Derived Mw (from scalar moment) 4.30-9.08, median 5.33. Per 5-yr bin (n / minMw / medianMw): 1976-79 1616/4.81/5.66; 1980-84 3035/4.81/5.53; 1985-89 3779/4.77/5.47; 1990-94 3756/4.84/5.47; 1995-99 4520/4.79/5.41; 2000-04 5771/4.58/5.32; 2005-09 9543/4.30/5.18; 2010-14 8494/4.56/5.15.  
License: Global CMT Project (Ekström/Nettles/Dziewonski, Lamont-Doherty). Free for research use with citation (Ekström et al. 2012, PEPI 200-201:1-9). No formal open-data license text is distributed with the ndk.  

> The canonical moment-tensor catalogue and the reference standard that ISC-GEM's 'direct' Mw values are keyed to. Two things make this file unusually valuable for magnitude-homogeneity work. (1) It is genuinely homogeneous in Mw: every event's magnitude comes from the same CMT inversion, so there is no scale-mixing at all — unlike ComCat/ISC where the preferred magnitude silently switches between mb, ML, mwc, mww. (2) Each event's FIRST ndk line is the triggering hypocentre from the USGS NEIC PDE, carrying that agency's mb and MS. So the file gives you mb, MS and Mw for the SAME event, in one download — exactly the cross-scale calibration set you need to build or validate mb->Mw and MS->Mw conversions before merging catalogues. 39,376 of 40,514 events carry a nonzero mb; 22,719 carry a nonzero MS; 21,598 (53.3%) carry BOTH. Hypocentre reference breakdown: PDE 21,841, PDEW 15,023, MLI 3,065, SWEQ 480, REB 57, PDEQ 29. CRITICAL RATE ARTEFACT: the GCMT analysis threshold dropped from ~M5.5 to ~M5.0 in 2004 when the project began routinely inverting smaller events — visible above as median Mw sliding 5.66 -> 5.15 and n per 5yr jumping from 5,771 to 9,543. Any GCMT-based rate or b-value study crossing 2004 MUST impose a fixed Mw cut (>=5.5 is the safe choice) or it will manufacture a spurious rate increase.

#### USGS ANSS ComCat — full global catalogue dump

**Why:** The single biggest gap. Nothing on GitHub mirrors ComCat globally — I searched repositories and code for parquet dumps, fdsnws CSV caches, and the well-known Kaggle 'Significant Earthquakes 1965-2016' NEIC extract, and got zero usable hits. ComCat is the only one of these catalogues that is (a) updated in near-real-time, (b) complete to small magnitudes, and (c) carries the full per-event magnitude provenance you need. It is essential for any forecasting work that needs recency or a low Mc. It is also the catalogue where magnitude inhomogeneity is WORST and therefore most important to handle explicitly: ComCat's 'preferred magnitude' silently switches type across the record — mb, ML, mwc, mwb, mww, mwr, Ms20 — chosen by an authoritative-agency + magnitude-type precedence rule, not by a single physical scale. Never feed ComCat 'mag' straight into a Gutenberg-Richter fit. Always pull the 'magType' column alongside 'mag' and either restrict to one type or apply documented conversions with their scatter propagated.

**How:**

```
earthquake.usgs.gov is policy-blocked from my sandbox, so this must be done from an unrestricted machine. The FDSN event service caps a single response at 20,000 events, so you must chunk. Base endpoint: https://earthquake.usgs.gov/fdsnws/event/1/query

Step 1 — count before you pull, so you can size the chunks:
  curl -sS 'https://earthquake.usgs.gov/fdsnws/event/1/count?starttime=1990-01-01&endtime=1991-01-01&minmagnitude=4.5'

Step 2 — loop year by year (drop to month by month for M>=2.5 or for post-2010 years, which exceed 20k):
  for Y in $(seq 1900 2026); do
    curl -sS --retry 5 --retry-delay 10 -o comcat_$Y.csv \\
      "https://earthquake.usgs.gov/fdsnws/event/1/query?format=csv&starttime=${Y}-01-01T00:00:00&endtime=$((Y+1))-01-01T00:00:00&minmagnitude=4.5&orderby=time-asc"
    sleep 2
  done

Step 3 — concatenate keeping exactly one header:
  head -1 comcat_1900.csv > comcat_all.csv; tail -qn +2 comcat_*.csv >> comcat_all.csv

The CSV header you should get is: time,latitude,longitude,depth,mag,magType,nst,gap,dmin,rms,net,id,updated,place,type,horizontalError,depthError,magError,magNst,status,locationSource,magSource. KEEP magType, magError, net, locationSource and magSource — those are the homogeneity-critical columns and the ones people most often throw away. Also keep status (reviewed vs automatic).

Expected size: M>=4.5 global 1900-2026 is roughly 350k-400k events, ~80-120 MB of CSV. Dropping to minmagnitude=2.5 balloons it to several million events (multi-GB) and is dominated by the dense US/Alaska/California networks — spatially very non-uniform, so do not treat a global low-M pull as a homogeneous global catalogue.

Alternative for the pre-2013 era: the historic ANSS composite catalogue search at https://ncedc.org/anss/catalog-search.html (also blocked from my sandbox). Note ComCat only became the catalogue of record on 2013-01-01; earlier content was ingested from the older ANSS composite and carries its heterogeneity.
```

**Size:** ~80-120 MB CSV for M>=4.5 (~350-400k events); multi-GB if you go to M>=2.5  
**License:** US Government work, public domain / no restrictions. Cite the contributing networks and USGS ComCat.

Daily, global, and it starts in 1979 — a 47-year baseline, which is long enough that a properly de-seasonalised, de-trended prospective test has genuine statistical power. It is also free of authentication, which removes the usual excuse for not running the test.

**How:**

```
CURRENT (S3 archive, after NCEI deprecated v01r02 in 2025):
  Base: https://archive.data.noaa.gov/cdr/
  Prefix: UMD_ESSIC/OLR_CDR/Daily/OLR-D-CDR_01B-21/
  List objects: https://archive.data.noaa.gov/cdr/?list-type=2&prefix=UMD_ESSIC/OLR_CDR/Daily/OLR-D-CDR_01B-21/&max-keys=1000  (parse the S3 XML <Key> elements)
  Filenames: OLR-Daily_v02r00_sYYYYMMDD_eYYYYMMDD.nc  (one per year), plus OLR-Daily_v02r00-preliminary_sYYYYMMDD_eYYYYMMDD.nc for the current year.
  Fetch each key as https://archive.data.noaa.gov/cdr/<full key>
LEGACY MIRROR (may still work): https://www.ncei.noaa.gov/data/outgoing-longwave-radiation-daily/access/
RESOLUTION DISCREPANCY TO RESOLVE ON DOWNLOAD: NCEI's product page states 1.0 x 1.0 degree for the daily CDR; the production fetcher I read annotates it as 2.5 degree. Read the netCDF lat/lon dimensions and trust those, not either document.
Complementary: NOAA Interpolated OLR (2.5 deg, daily, 1974-06→present) at https://psl.noaa.gov/data/gridded/data.olrcdr.interp.html — the longer but coarser record, and the one with the 1978 satellite-transition gap.
```

**Size:** ~50–150 MB per annual netCDF; ~3–7 GB for 1979–2026  
**License:** US Government public domain  

#### MODIS Land Surface Temperature via ORNL DAAC REST API (no authentication)

**Why:** The point-scale counterpart to OLR for the thermal-anomaly hypothesis: 1 km, twice-daily (day + night overpass), 2000→present. The night-time LST band is the one that matters, since daytime LST is dominated by insolation and land cover. 25-year baseline at 1 km is genuinely well-suited to a matched case-control design (epicenters vs. spatially/seasonally matched controls).

**How:**

```
API base: https://modis.ornl.gov/rst/api/v1/  — no auth, rate limit ~1 request/second (ORNL fair-use).
Products: MOD11A1 (Terra, daily 1 km) preferred; MOD11A2 (8-day composite) as fallback; add MYD11A1 (Aqua) for a second daily overpass.
Pattern: /subset?latitude={lat}&longitude={lon}&product=MOD11A1&band=LST_Night_1km&startDate=A{YYYYDDD}&endDate=A{YYYYDDD}&kmAboveBelow=..&kmLeftRight=..
Design note that determines whether the test is worth anything: pull BOTH epicenter windows (±14 days minimum, to establish a local seasonal baseline) AND matched random control locations drawn from the same lat/lon and season distribution but time-shifted by ±60–180 days. Without the matched controls the seasonal/diurnal/land-cover confound will manufacture a spurious signal.
Bulk alternative for gridded tiles: LP DAAC via `pip install earthaccess` (free NASA Earthdata login), products MOD11A1.061 / MYD11A1.061.
Ocean pixels are NaN — screen offshore epicenters out explicitly rather than letting them become silent zeros.
```

**Size:** Point-subset approach: tens of MB. Full gridded tiles: hundreds of GB — use the point API.  
**License:** LP DAAC/ORNL DAAC: no restriction on use, sale, or redistribution  

#### USGS NWIS groundwater levels — continuous and discrete

**Why:** The only multi-decade, national-scale, openly-published groundwater archive with sub-hourly sampling at a subset of wells. Supports both the hydrological-loading hypothesis (seasonal aquifer mass) and the pore-pressure/water-level precursor hypothesis. The USGS explicitly maintains a set of wells instrumented for earthquake response.

**How:**

```
1. `pip install dataretrieval` (USGS's own client; verified fetchable from PyPI).
2. Continuous/high-frequency water levels come through the INSTANTANEOUS VALUES service, not the groundwater-levels service — this trips people up:
   https://waterservices.usgs.gov/nwis/iv/?format=json&sites={siteno}&parameterCd=72019&startDT=2015-01-01&endDT=2020-01-01
   (72019 = depth to water level below land surface; 62610/62611 = groundwater level above datum.)
3. Discrete/periodic measurements: https://waterservices.usgs.gov/nwis/gwlevels/?format=rdb&sites={siteno}&startDT=...&endDT=...
4. Site discovery by state/county/bbox: https://waterservices.usgs.gov/nwis/site/?format=rdb&stateCd=ca&siteType=GW&hasDataTypeCd=iv
5. Sampling varies per well — 1-min, 15-min, or hourly. Record the per-site interval; do not assume uniformity.
6. Background + the curated earthquake-response well set: https://www.usgs.gov/mission-areas/water-resources/science/groundwater-level-response-earthquakes
JAPAN EQUIVALENT (purpose-built for earthquake prediction, arguably better-designed than the US network): Geological Survey of Japan / AIST integrated groundwater + strain network, 16 stations around the Nankai Trough, online at https://gbank.gsj.jp/wellweb/GSJ_E/index.shtml
```

**Size:** Per-well 15-min over 20 years ≈ 700K points ≈ 20–40 MB; a 200-well regional set ≈ 5–10 GB  
**License:** US Government public domain  

#### EarthScope / PBO borehole strainmeters and pore-pressure sensors

**Why:** The most direct measurement that exists of the quantity every one of these hypotheses is really about — crustal strain at 1e-9 to 1e-8 resolution, sampled at 1 Hz, ~75 instruments, ~2005→present, co-located with 23 pore-pressure sensors. It resolves the solid-Earth tide with high SNR, so it independently validates the computed tidal strain; and it is the instrument that would actually see a pre-slip/nucleation transient if one existed. Any serious 'exotic precursor' program that skips strainmeters is testing proxies when the direct measurement is available.

**How:**

```
`pip install earthscopestraintools` (verified fetchable from PyPI), then:
1. Level-2 processed strain (tidal + barometric corrections applied, XML/ASCII) — EarthScope/GAGE archive; an EarthScope account is required for the XML product.
2. Raw 1 Hz and 20 Hz strain as miniSEED via FDSN dataselect at the SAGE/IRIS DMC and NCEDC — network codes PB (PBO borehole). Use obspy's FDSN client against https://service.iris.edu/fdsnws/dataselect/1/ or https://service.ncedc.org/fdsnws/dataselect/1/ .
3. Pore pressure: 1 Hz from 23 boreholes, SEED at the DMC or time-stamped ASCII from GAGE.
4. Station list + per-station notes/logs: https://www.unavco.org/data/strain-seismic/bsm-data/bsm-data.html
BOTH IRIS/SAGE AND NCEDC ARE HARD-BLOCKED FROM THIS ENVIRONMENT (explicit policy denial), so there is no partial workaround — this one is entirely on the human.
Practical caveat: BSM data carries large instrumental transients (borehole curing/relaxation over the first ~2 years after install, offsets at maintenance events). Use Level-2 or budget real time for detrending.
```

**Size:** 1 Hz, 75 stations, 15 years ≈ several TB raw; Level-2 daily/hourly products are ~GB  
**License:** Free and open (NSF-funded); EarthScope acknowledgement required  

#### Ocean tide loading model grids (FES2014 / TPXO / GOT) — for the tidal-stress channel

**Why:** My verified offline computation covers the SOLID Earth tide only. Within ~100–200 km of a coast, ocean tidal loading contributes stress comparable to or larger than the body tide, and it is phase-shifted relative to it. A tidal-triggering test on a coastal or subduction-zone catalog that omits ocean loading is not merely less precise — it is computing the wrong phase, which can invert the sign of a reported correlation. These grids are the one piece of the tidal calculation that cannot be generated locally.

**How:**

```
1. FES2014b (recommended, highest quality): register free at AVISO+ (https://www.aviso.altimetry.fr/en/data/data-access/registration-form.html), select the FES2014 product, then download via their FTP/HTTPS. Load-tide grids are a separate product from the ocean-tide elevation grids — you need the LOAD grids (fes2014b_elevations_and_load/load_tide/).
2. TPXO9-atlas: request an academic licence at https://www.tpxo.net/ (free for research; a one-line email form).
3. GOT4.10c: available from NASA GSFC.
4. Then either: (a) `pip install pyTMD` (already verified) which reads FES/TPXO/GOT directly and has predict.ocean_load; or (b) SPOTL (Agnew), https://igppweb.ucsd.edu/~agnew/Spotl/spotlmain.html, which is the reference implementation and ships with some ocean models.
Once you have the grids the whole tidal-stress pipeline is offline and reproducible.
```

**Size:** FES2014 load-tide grids ~5–20 GB; TPXO9-atlas ~2 GB  
**License:** Free for research with registration; redistribution restricted — do not re-host

**Why:** Gives per-well stimulation date, surface location and total base-fluid volume for 210,000+ wells since 2011 — i.e. the short-duration, high-rate injection forcing that is distinct from long-term wastewater disposal. #### Molchan error diagram and ROC evaluation methodology — primary sources

**Why:** The alarm-based evaluation framework. Molchan diagram plots miss rate nu = c/(a+c) = 1 - H against space-time alarm rate tau = (a+b)/(a+b+c+d) across alarm thresholds; the tau + nu = 1 diagonal is the random-guess strategy, and only trajectories significantly BELOW it beat chance. The area above the trajectory is the Area Skill Score. This is the correct frame for judging anything phrased as 'a prediction' rather than 'a rate forecast', and it is the frame that has repeatedly shown claimed precursors to be no better than random once alarm volume is accounted for. Note the standard critique: plain ROC uses a spatially uniform earthquake distribution as its reference, which is unrealistically weak, so Molchan is preferred in seismology.

**How:**

```
Primary: Molchan, 'Structure of optimal strategies in earthquake prediction', Tectonophysics 193, 267-276 (1991) and Molchan, 'Earthquake prediction as a decision-making problem', Pure Appl. Geophys. 149, 233-247 (1997). Zechar & Jordan, 'Testing alarm-based earthquake predictions', GJI 172(2), 715-724 (2008), doi 10.1111/j.1365-246X.2007.03676.x — introduces the Area Skill Score and the Molchan trajectory significance test. Zechar & Jordan, 'The area skill score statistic for evaluating earthquake predictability experiments', Pure Appl. Geophys. 167, 893-906 (2010). Executable versions already fetched: plot_Molchan_diagram, plot_ROC_diagram, plot_concentration_ROC_diagram in https://raw.githubusercontent.com/SCECcode/pycsep/main/csep/utils/plots.py .
```

**Size:** 4 PDFs  
**License:** Copyrighted; pyCSEP implementations are BSD 3-Clause  

#### M8 and CN intermediate-term prediction algorithms — prospective test record

**Why:** The longest-running genuinely prospective earthquake-prediction experiment (M8 tested from 1985, real-time since 1992) and the main historical claim that alarm-based prediction works. Any new model claiming predictive skill will be compared to it, and the honest reading of its record is contested. ## Notes from each scout

**Global catalogs:** WHAT I ACTUALLY VERIFIED vs. WHAT I INFERRED  Every URL in fetchable_now was curl'd and the bytes inspected — I did not mark anything verified:true on the strength of a search-result snippet. Byte counts, row counts, date ranges, Mw ranges and the direct/proxy splits are all computed from files sitting on this disk, not quoted from papers. Where I cite a published figure instead (e.g. ISC-EHB's 208,480 events, the ISC-GEM "complete to Mw5.6 from 1964" statement) it is from web sources, not from data I hold, and I have flagged it as such inline.  THE HEADLINE RESULT  The best single dataset for this task — ISC-GEM v12.1, the current release of the only deliberately magnitude-homogeneous global instrumental catalogue — turned out to be fully fetchable from GitHub, which I did not expect going in. 19,814,474 bytes, 74,159 rows, 1904-2021. Its SHA-256 matches a checksum committed independently elsewhere in the same repo, and its embedded header carries the complete ISC version history through "Version 12.1 - released on 2025-11-26". The official ISC download is gated behind a name/email/affiliation form plus a CAPTCHA, so a working mirror is genuinely valuable. Caveat stated plainly: same-repo checksum proves integrity, not provenance. Diff it against the official file before publishing.  Second headline: the full GCMT combined catalogue (jan76_dec13.ndk, 40,514 events, 16.4 MB) is also on GitHub, inside a seismology tool's example-data directory.  MAGNITUDE HOMOGENEITY — THE PART THAT WRECKS b-VALUES  This was the sharpest question asked and the answer is not reassuring.  1. ISC-GEM is homogeneous in UNITS but not in PROVENANCE. Every event carries an Mw, but in v12.1 only 51,228 of 74,159 (69%) are directly measured; 22,931 (31%) are proxy values regressed from re-computed MS/mb. That split is violently time-dependent: 3-7% direct before 1960, 15.7% in the 1960s, 26.5% in the 1970s, 78.2% in the 1980s, 93.9% in the 2000s, 95.1% in the 2020s. A study spanning 1900-2020 is fitting a regression artefact for its first half and real moment tensors for its second. The 's' column ('d'/'p') is how you tell them apart and most published analyses I am aware of do not condition on it. Filter to s=='d' for a truly homogeneous sub-catalogue (at the cost of losing nearly everything before 1976), or carry mw_unc into the likelihood — ISC-GEM ships per-event magnitude uncertainty and A/B/C quality flags precisely so you can.  2. GCMT is the cleanest scale available — single inversion method, no scale-mixing at all — but has a hard rate discontinuity at 2004 when the analysis floor dropped from ~M5.5 to ~M5.0. Visible in my binning: median Mw slides 5.66 (1976-79) to 5.15 (2010-14), and events per 5 years jumps 5,771 to 9,543 across 2004. Any rate or b-value comparison crossing 2004 without a fixed Mw>=5.5 cut will invent a seismicity increase that is purely an analyst-threshold change.  3. ComCat is the worst offender and the one people reach for first because it is easy. Its 'mag' column silently changes physical scale between mb, ML, mwc, mwb, mww, mwr and Ms20 according to an agency/type precedence rule. Always pull magType alongside mag. Never fit GR to raw ComCat 'mag'.  4. Unexpected bonus: jan76_dec13.ndk is a ready-made cross-scale calibration set. The first line of every NDK record is the triggering USGS PDE hypocentre with that agency's mb and MS, while the moment tensor gives Mw for the same event. 39,376 events carry mb, 22,719 carry MS, and 21,598 (53.3%) carry BOTH alongside Mw. If you need to derive or validate mb->Mw and MS->Mw conversions before merging catalogues, that is 21,598 triples in a single 16 MB file with no joining required. This is the most useful thing I found that nobody asks for by name.  5. ISC-EHB is for depth, not magnitude. Its magnitudes are inherited ISC mb/MS, not homogeneous Mw. Use it for WHERE (depth-phase-constrained hypocentres) and ISC-GEM/GCMT for HOW BIG. Do not treat it as a magnitude source.  COMPLETENESS IS NON-STATIONARY IN WAYS THE HEADLINE NUMBERS HIDE  ISC-GEM's advertised "complete to Mw5.6 from 1964" is a global average and conceals real structure. My per-decade counts of Mw>=5.5 events show 1900s 197, 1910s 626, 1920s 1612 — the 1910s and the 1940s (1,360) are visibly depressed relative to neighbours, which is the two World Wars shutting down station networks and interrupting bulletin production. Do not model pre-1964 completeness as a constant.  VERSION DRIFT IS LARGE ENOUGH TO CHANGE CONCLUSIONS  I verified three ISC-GEM vintages and they differ enormously: v3 = 24,376 rows, v5.1 = 28,112 rows (51.4% direct Mw), v12.1 = 74,159 rows (69% direct Mw). That is nearly a tripling, driven by the Extension Project lowering the threshold to continental Mw5.0 and re-assessing 1964-1970 events. If you have b-values published against an older ISC-GEM, re-run them — and check ISC's update_log, which records exactly which events changed.  DEAD ENDS, REPORTED HONESTLY  - No global ComCat dump exists on GitHub. I searched repositories and code for parquet dumps, cached fdsnws CSV, and the well-known Kaggle NEIC extract. Zero usable hits. This is the biggest remaining gap and it needs a human. - No ISC-EHB global dump on GitHub. Searching "isc-ehb" in CSVs returned only a Himalayan study's per-event agency-comparison tables — a dozen rows each, useless as a catalogue. - No ISC Bulletin on GitHub beyond a single 73 KB Africa-region ISF extract (which I verified and which is genuinely useful as a format specimen for testing an ISF parser before a multi-GB download). - No GHEC data on GitHub. Only references inside IBM Helm-chart license manifests and one script that fetches it at runtime. - The Nora-Research-Lab ISC-GEM GeoParquet repo advertises parquet files that ARE NOT IN IT. I cloned it: README.md and metadata.json only, and the raw URLs 404. The repo was created 2026-09-08, one day before this search. Its metadata.json is still worth reading — it correctly disambiguates ISC-GEM's repeated column names ('q' appears three times, 'unc' twice) — but do not count on the data. - huggingface.co, globalcmt.org, emidius.eu, earthquake.usgs.gov, isc.ac.uk, service.iris.edu, seismicportal.eu and zenodo.org are all egress-blocked here. I did not attempt to route around any of them.  PRACTICAL GOTCHAS THAT WILL COST YOU AN HOUR EACH  - ISC-GEM's '#' preamble length CHANGES BETWEEN VERSIONS. I found real repos hardcoding skiprows=109, skiprows=97, skiprows=56 and header=97 against different vintages. Never hardcode it — use comment='#' or detect the header line. - ISC-GEM CSV fields are whitespace-padded inside the commas (" 1976-01-01 01:29:39.34 , -28.814 , ..."), so a naive split leaves you with untrimmed strings. Strip every field. - The column schema widened after v5.1: 24 columns (through v5.1) vs 31 columns (v12.1, adds str1/dip1/rake1/str2/dip2/rake2/type). Code written against one will silently misalign against the other. - GCMT NEW_MONTHLY filenames are irregular — mostly {mmm}{yy}.ndk but with sept05.ndk, june05.ndk, july05.ndk variants. Enumerate the directory; do not generate names. - NDK records are exactly 5 lines, so concatenating files with cat is safe. But the hypocentre line's region name contains spaces, so whitespace-splitting that line is fragile — I hit exactly this and had to switch to a regex for the date field. Use fixed-width parsing per the NDK spec, or obspy. - The obspyDMT clone is ~174 MB, almost all of it the 166 MB QuakeML set that covers LESS time (1976-2005) than the 16 MB ndk file. Take the ndk; skip the QuakeML unless you specifically need it. - CC-BY-SA 3.0 on ISC-GEM and GHEC is SHARE-ALIKE. Derived catalogues you redistribute inherit the license. Worth checking against your intended publication terms early rather than late.  SUGGESTED MINIMAL STACK  For a global forecasting study: ISC-GEM v12.1 as the homogeneous-Mw backbone (1904-2021), filtered on s=='d' where you need strict homogeneity and with mw_unc propagated where you do not; GCMT jan76_dec13.ndk plus the monthly files for moment tensors, focal mechanisms and the mb/MS/Mw calibration triples (1976-2015); then a human-fetched ComCat pull for 2021-present recency and for any low-Mc regional work, with magType retained and conversions applied explicitly. Add GHEC only if you need M>=8 recurrence priors, and model the 1904 completeness break rather than concatenating. RESOLUTION MISMATCHES THAT DETERMINE WHETHER A TEST IS EVEN POWERED  Several of these channels have a structural mismatch between what is archived and what the hypothesis requires, and it is worth naming these before anyone spends a month on acquisition:  - ULF electromagnetic: the literature emphasises 0.01–0.1 Hz, but 1-minute geomagnetic data has a Nyquist of 8.3 mHz. The 1-second product that can actually reach that band only begins 2011-06-13 and only at a subset of observatories. So the channel offers a 35-year baseline at the wrong bandwidth, or the right bandwidth with a 15-year baseline — never both. - GRACE: monthly sampling, ~300 km resolution. Fine for seasonal hydrological-loading modulation. Cannot resolve a days-to-weeks precursor even in principle. Plus a real 11-month GRACE→GRACE-FO gap (2017-07 to 2018-05) that must not be silently interpolated across. - Ionospheric TEC: IONEX is 2.5° x 5°, roughly 275 x 450 km per cell. A localized anomaly is averaged away at that resolution. This is not speculative — the japan-geohazard README documents finding exactly this, and states in its conclusions that "low-resolution global indices cannot detect local precursors." Madrigal's 1° x 1° / 5-min product or receiver-level GNSS-TEC is the minimum for a fair test. - Radon: soil radon is dominated by barometric pressure, temperature and soil moisture. IRON is valuable specifically because it ships co-located temperature and humidity; any radon dataset without concurrent meteorological covariates cannot support a claim, because the confound is larger than the putative signal.  DATA-INTEGRITY ISSUES SPECIFIC TO PROSPECTIVE TESTING  A prospective test needs archives with known vintage, and several of these fail that by default. Geomagnetic "definitive" data is reprocessed after each calendar year, so a value retrieved today is not the value that was available in real time — for a genuinely prospective design you need the provisional/quasi-definitive product at its original latency, not the definitive product backfilled. Earthquake catalogs are revised retroactively (magnitudes, locations, and even event existence). Oklahoma injection volumes before 2016-03-27 were VOLUNTARILY reported and are incomplete; Texas daily reporting exists only inside Seismic Response Areas and only from each area's designation date. FracFocus is operator self-reported with staggered state mandates and covers stimulation only, never disposal. In all these cases the data-generating process changed mid-record, which will manufacture apparent temporal structure that has nothing to do with the Earth. Freeze and version every download with its retrieval date. GOTCHAS WORTH KNOWING. 1. The two HKJ files report identical byte sizes (21,417,416). That is a fixed-width-format coincidence on an identical grid, not duplication — I checked the values and the aftershock rates are uniformly higher. Do not dedupe them by size. 2. floatCSEP case_e (the Italy experiment) sets catalog: query_bsi, so it needs INGV webservices, which is policy-blocked here. The forecasts are fetchable but the ground truth is not. Cases b, c, f, g, h, i and j bundle their catalogs and are fully self-contained. 3. EarthquakeNPP dataset filenames are not guessable from the README — I had to read Experiments/ETAS/config/*.json to recover them. The real paths are Datasets/ComCat/ComCat_catalog.csv, Datasets/SCEDC/SCEDC_catalog.csv, Datasets/QTM/SanJac_catalog.csv, Datasets/QTM/SaltonSea_catalog.csv, Datasets/WHITE/WHITE_catalog.csv (directory is uppercase WHITE, not White, despite the README link), Datasets/ETAS/ETAS_California_catalog.csv and ETAS_California_incomplete_catalog.csv. The Japan_Deprecated catalog is not at any path I probed and its config JSON is absent; it likely lives in a git submodule, which raw.githubusercontent cannot serve. 4. SCECcode/pycsep and cseptesting/pycsep are the same repository (the former redirects). Both raw paths work; I used SCECcode. 5. Magnitude thresholds differ by experiment and this is a real trap: RELM and the long-term experiments use M>=4.95, the California next-day database uses M>=3.95, CSEP-Italy targets 3.95<=ML<4.95 separately from larger shocks, EarthquakeNPP goes down to M0.6. A model tuned at one threshold will not transfer. 6. The testing region and the collection region are different polygons. Events in the collection area inform rates but are not scored. Mixing them silently corrupts the N-test. Both are in the fetched region files. 7. Poisson consistency tests assume the earthquake count is Poisson-distributed; it is overdispersed in reality. This is a known, documented weakness of the classic N-test and is why negative-binomial and binary/binomial variants exist (pyCSEP ships binomial_evaluations.py). The Mizrahi et al. 2024 Reviews of Geophysics review covers this — read it before choosing your metric, or you will optimise against a test the field has already partly abandoned.
